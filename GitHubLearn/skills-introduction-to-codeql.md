# GitHub Skills: Introduction to CodeQL

## Skills Covered
- Understand the purpose and use cases of GitHub Code Scanning and CodeQL static analysis
- Enable CodeQL analysis workflows and trigger scans in pull requests to track vulnerabilities
- Learn how to review, classify, and manage security alerts generated by scans
- Practice fixing real code vulnerabilities and verifying the results with CodeQL

## CodeQL Workflow
1. **Enable CodeQL scanning**: Turn on Advanced Security in the repository settings and enable the default CodeQL setup. This will automatically trigger the first scan.
2. **Create a pull request with a simulated vulnerability**: Edit `routes.py` and introduce a SQL injection-style statement such as `"SELECT * FROM books WHERE name LIKE '%" + name + "%'"`, then create a new branch and open a pull request.
3. **Wait for CodeQL analysis**: After the pull request is created, CodeQL scans the changes and generates security alerts with data flow tracing from the source to the vulnerable sink.
4. **Review and classify alerts**: Open `Security > Code Scanning` to review alerts, including the vulnerability type, CWE identifier, remediation suggestions, and audit history.
5. **Close and reopen alerts**: You can mark an alert as closed in the UI, for example if it is only used for testing, and later reopen it with a reason. The process keeps an audit trail.
6. **Fix the vulnerability**: Rewrite the SQL query using parameterized syntax and commit the fix directly to `main`. CodeQL will run again and close the alert if the issue is resolved.

## Additional Notes
- GitHub Code Scanning is part of GitHub Advanced Security (GHAS) and can be integrated into CI/CD workflows for SAST analysis
- CodeQL is a static analysis tool that can detect common vulnerabilities such as SQL injection and XSS using built-in query suites
- All GHAS features are available for public repositories at no cost, while private repositories require a paid plan
- The default CodeQL setup automatically detects supported languages, uses default rule sets, and runs scans on pull requests or scheduled workflows
- **CWE (Common Weakness Enumeration)** is a standard system for categorizing software weaknesses, and CodeQL often uses CWE IDs to label issues
- In security analysis, **source** refers to where user input enters the system, and **sink** refers to where that input is used. CodeQL can visualize the full data flow between them
